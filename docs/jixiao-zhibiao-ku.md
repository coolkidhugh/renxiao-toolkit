# 绩效指标库怎么搭

## 定义

**绩效指标库**是企业沉淀的一套标准化指标字典：每个指标有统一的名称、定义、计算公式、数据来源、统计周期、适用岗位/部门范围与注意事项。它服务于目标分解、绩效考核、经营分析与人对齐，减少「同名不同义」和临时拍指标。

指标库 ≠ 每个人当季的绩效合约。合约从库中**选用并裁剪**；库负责「定义正确、来源可靠、可复用」。

## 公式 / 步骤

### 单条指标的「指标卡」字段（建议）

| 字段 | 内容 |
|---|---|
| 指标名称 | 对外统一用名 |
| 定义 | 一句话说明测什么 |
| 公式 | 可计算的表达式 |
| 单位 | 元、%、件、小时等 |
| 数据来源 | 系统/报表/人工采集责任部门 |
| 统计周期 | 日/周/月/季/年 |
| 取值逻辑 | 时点值 / 期间累计 / 平均值 |
| 方向 | 越高越好 / 越低越好 / 区间达标 |
| 适用对象 | 岗位族、层级、部门 |
| 常见误用 | 易错口径、重复计量提醒 |
| 版本与生效日 | 变更可追溯 |

### 搭建步骤

1. **盘点现有指标**：从经营报表、部门 KPI、历史绩效表收集，先去重、合并同义项。
2. **分层分类**（示例）：
   - 公司级结果指标（营收、利润、现金流、人效等）
   - 过程/运营指标（交付周期、合格率、响应时效等）
   - 组织与人才指标（关键岗位满编率、骨干保留等）
   - 项目类 / 里程碑类（用完成定义，不只用分数）
3. **写清公式与来源**：没有稳定数据源的指标不入库，或标为「试点」。
4. **做加减法**：库要能用，不求大而全。优先高频、强对齐战略的指标；删除无法取数或从不使用的项。
5. **与目标体系挂钩**：明确公司目标 → 部门目标 → 个人指标时，如何从库中选、如何设权重与互斥规则（避免人人背同一营收导致重复问责不清）。
6. **试点与培训**：选 1～2 个部门试填绩效合约；培训管理者「选指标」而非「发明指标」。
7. **治理节奏**：指定指标 Owner（通常是业务 + HR/财务共建）；按季或按半年评审增删改；重大口径变更发版本说明。

### 选用原则（写进使用说明）

- **少而精**：个人指标数量可控，结果类与过程类搭配。
- **可影响**：任职者有实质影响力；纯外部环境指标慎作主指标。
- **可验证**：周期结束能取到数，争议有裁定规则。
- **不重复**：同一结果不要在多人合约里无分拆地重复 100% 背负，除非角色清晰（如共担需写清分摊）。

## 适用场景

- 绩效体系从「打分表」升级到「目标与指标」
- 多事业部指标口径打架，需要统一字典
- 人效与经营分析希望和绩效语言一致
- 数字化 HR/OKR/绩效系统上线前的主数据准备

不适用：用指标库替代战略对话；或把库变成形式主义的超长清单却无人维护。

## 绩效指标库和 OKR 什么关系？

可以并存：OKR 强调目标与关键结果的对齐与节奏；指标库提供可复用的量化定义与数据来源。OKR 的 Key Result 应从库中选或经治理后入库。没有库时，OKR 也容易出现口径漂移。

## 一个岗位要设多少个绩效指标？

实务上宜少而清晰，常见是少量结果指标 + 必要过程指标，具体数量视角色复杂度而定。指标过多会稀释焦点、增加取数与复议成本。宁可用好的目标描述补充「质量与行为」，也不要堆十几个无法跟踪的数字。

## 定性工作怎么进指标库？

用**完成定义（DoD）**、里程碑、服务级别（如按时交付率、差错率）、抽样评价标准等可验证方式，而不是「工作态度 1–5 分」单独充当主结果。确需行为项时，使用行为锚定量表，并限制权重。

## 指标谁有权新增或修改？

建议：业务提出 → 数据源部门确认可取数 → HR/绩效管理员审核命名与重复 → 指标委员会或指定 Owner 批准生效。禁止考核前临时改口径。变更记录保留版本号。

## 指标库搭好后多久更新一次？

与战略与组织调整同步：至少每年全面审一次；每季度处理新增业务、下线废弃指标。系统字段与报表字段变更时，同步改指标卡，避免「库」与「数」脱节。
